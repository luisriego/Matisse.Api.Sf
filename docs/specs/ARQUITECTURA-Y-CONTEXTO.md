# Radiografía Técnica y Contexto de `Matisse.Api.Sf`

## 1. Resumen Ejecutivo del Sistema

`Matisse.Api.Sf` es el backend API para la administración integral de un condominio (**Edifício Matisse**), construido sobre **PHP 8.3**, **Symfony 6.4 LTS**, **Doctrine ORM 3** (mapeo XML libre de anotaciones en dominio) y **PostgreSQL 16 + `pgvector`**.

Sigue una combinación de:
- **Vertical Slice Architecture + Hexagonal Architecture (Ports & Adapters)**: Cada contexto de negocio (`src/Context/<BoundedContext>`) aísla `Domain/`, `Application/` e `Infrastructure/`.
- **DDD Táctico (Domain-Driven Design)**: Aggregate Roots que extienden [`AggregateRoot`](file:///home/luisriego/Dev/PHP/Matisse.Api.Sf/src/Shared/Domain/AggregateRoot.php), Value Objects inmutables, Domain Services, Policies, Guards y Domain Events inmutables (`readonly class` que extiende [`DomainEvent`](file:///home/luisriego/Dev/PHP/Matisse.Api.Sf/src/Shared/Domain/Event/DomainEvent.php)).
- **CQRS (Command Query Responsibility Segregation)**: Buses diferenciados (`command.bus` transaccional vía Doctrine middleware y `query.bus` de solo lectura) junto con inyección directa de Handlers en controladores `final readonly`.
- **Event Sourcing Híbrido + Outbox Transaccional**: Los agregados graban eventos de dominio (`$this->record(...)`); [`DomainEventCollectorSubscriber`](file:///home/luisriego/Dev/PHP/Matisse.Api.Sf/src/Shared/Infrastructure/Persistence/Doctrine/DomainEventCollectorSubscriber.php) los recolecta en los ciclos `onFlush`/`postFlush` de Doctrine, los persiste en la tabla `event_store` mediante [`DoctrineStoreEventRepository`](file:///home/luisriego/Dev/PHP/Matisse.Api.Sf/src/Context/EventStore/Infrastructure/Persistence/Doctrine/DoctrineStoreEventRepository.php) y los despacha síncronamente a los suscriptores registrados. Algunos casos de uso (como el saldo de cuenta en `GetAccountBalanceQueryHandler`, el estado del `Setup` o los snapshots de `BillingPolicy`) reconstruyen estado directamente desde el `EventStore`.
